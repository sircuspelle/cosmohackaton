# cosmohackaton

## Inception

### ключевая задача

- Сервис самостоятельно *получает открытые данные, выделяет значимые факторы, оценивает их развитие и сравнивает возможные окна проведения работ*
- Каждый *вывод* должен быть связан с исходными наблюдениями или прогнозами

### предметная область

- положение станции
- состояние космической среды
- ожидаемые события

#### особенности

- разная частота обновления
- неодинаковая точность
- частично произошедшее, частично прогноз, частично статистика

### входные и выходные данные

#### входные

- планируемое время
- длительность сеанса

#### выходные

- внешние факторы
    - оценка их значимости
    - время проявления
- варианты окон
- недостающие данные

### исследовательская часть

#### космическая погода

#### космический мусор

## Elaboration

1. запросы к API по данным
2. сервисы собирают метрики
3. компаратор сравнивает окна
4. интерфейс

## Construction

у себя локально настроить `git config core.hooksPath .githooks`

## Требования к проекту

### Функциональные требования (полный набор)

**Высокий приоритет:**
- [x] **Исследовательская часть:** Реализована оценка не менее двух различных механизмов воздействия (космическая погода, мусор, тепловой режим, связь и т.д.).
- [x] **Запрос пользователя и траектория:** Выбор текущей обстановки или исторической даты, задание начала и длительности ВКД (1-8 часов), периода поиска вариантов (до 24 часов).
- [x] **Расчет траектории:** Получение орбитальных данных МКС и расчёт положения станции. Использование этих данных для оценки факторов.
- [x] **Сравнение и выбор окна:** Сравнение не менее двух окон одинаковой длительности. Выбор предпочтительного варианта на основе взвешенного риска или объяснение невозможности выбора. Пересчет при сдвиге плана.
- [ ] **Интерфейс:** Реализация бота (Telegram), веб-сервиса или мини-приложения для самостоятельного запроса пользователя.
- [x] **Форма результата:** Выгрузка результатов в машиночитаемом формате (JSON/CSV) с сохранением параметров запроса.

**Средний приоритет:**
- [x] **Мониторинг и прогноз:** Автоматическое и принудительное обновление данных из открытых источников. Учет времени последнего обновления.
- [x] **Учет недостатка данных:** Отсутствие данных не приравнивается к нулевому риску. Недостаток сведений обрабатывается корректно (отмечается как неполнота).
- [ ] **Объяснение предупреждений:** Вывод для каждого предупреждения: значение для ВКД, источник, время публикации, модель/правило и обоснование уверенности.

**Низкий приоритет:**
- [ ] **Исторический режим (Replay):** Возможность запустить сервис на произвольную дату в пределах 1 мая — 30 июня 2024 года с отсечением информации, доступной только на тот момент.

### Нефункциональные требования (минимальный набор)

**Высокий приоритет:**
- [x] **Надёжность и обработка сбоев:** При сбое источника система не падает, а сохраняет доступ к уже полученным данным с пометкой об их устаревании.
- [x] **Архитектура и качество кода:** Понятная структура, разделение получения данных, расчётов и интерфейса.

**Средний приоритет:**
- [x] **Временная и пространственная согласованность:** Все расчеты и моменты времени ведутся в едином формате (базово — UTC).
- [x] **Документация и воспроизводимость:** Наличие инструкций по запуску и описания источников данных. Допускается кеширование и локальные копии архивов.
